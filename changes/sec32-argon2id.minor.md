**Headline:** Admin passwords are now hashed with Argon2id, a password can be at most 1,024 characters, and the session cookie carries the `__Host-` prefix when it is Secure.

### Changed
- **Argon2id password hashing (SEC.32).** New hashes use Argon2id (`argon2-cffi`) at OWASP's minimum cost, 19 MiB, 2 passes and 1 thread, in place of PBKDF2. The cost is the `password_hash` settings section (`memory_kib`, `time_cost`, `parallelism`; `PLANETGEN_PASSWORD_HASH_MEMORY_KIB`, `_TIME_COST`, `_PARALLELISM`). `verify_password` sends a stored hash by its prefix, so the PBKDF2 and scrypt hashes older installs hold still work, and `needs_rehash` is true for those and for an Argon2id hash made with other numbers than the settings name; the next successful login stores a new hash. `update.sh` installs `argon2-cffi` with the other libraries.
- **A password is at most 1,024 characters.** `validate_password_policy` refuses a longer one with the message "password must be at most 1024 characters", and `verify_password` and `hash_password` take no more, so a sign-in attempt does a fixed amount of work. A longer password at sign-in fails like a wrong one. The minimum stays 12 with the blocklist.
- **The session cookie is `__Host-pg_admin_session`.** When the cookie is Secure (everywhere except `admin_cookie_insecure` for local development) its name carries the `__Host-` prefix, which makes the browser refuse a copy set by a sibling sub-domain or over plain HTTP. Everyone signs in once more after this release, because the old cookie has a different name. With `admin_cookie_insecure` the name stays `pg_admin_session`.
