**Headline:** The setting for the most workers on the host is gone, and the Queue page's workers tile counts the unit and job processes the ledger has running now.

### Removed
- **OPS.235 slice 1d.** The `queue.max_host_workers` setting (with `config.schema.json`, `config.json.example` and `docs/reference/config.md`, regenerated by `planetgen config docs`) and the code that read it: `workers.host_worker_cap`, `host_worker_processes`, `count_worker_processes`, `live_worker_count`, `REFUSED_KEY` and `WORKER_COMMAND`. Nothing started RQ workers since slice 1b, so there was nothing for the cap to refuse. A `config.json` that still names `queue.max_host_workers` would fail `planetgen config check` as an unknown key, so `./update.sh` now removes it once (see Added).
- `INSTALL.md`'s advice to lower that setting on a small host: the memory gate and controller size how many units run at once.
- The three other worker settings stay: `interactive_workers` and `long_workers` still set the places the gate keeps for short and long jobs and the tile builder's share of the cores, and `maintenance_workers` still caps the maintenance class in the launcher.

### Added
- `settings.RETIRED_OPTIONS` and `settings_writer.retire`: the options a release retired, taken out of `config.json` alone (no default added, no other stale key touched) with a settings backup, an audit row `config.retire` and a printed line per key. `planetgen config retire` runs it and `./update.sh` calls it after the database migration (`retire_config_options`); it never stops an update. Reuse: `plan_update`'s stale-key path (`_load_document`, `_drop`, `_write`, `_audit`, `Change`); not `update`, which also adds every missing default.

### Changed
- `GET /api/admin/work` `status.workers_active` is now `controls.running_units`: the jobs the ledger has `running`, in every run and class. It counted RQ workers, which no run uses. The page's tile reads the same number.
- `tests/test_maintenance_lane.py` keeps only its queue-of-a-kind test; the rest tested the worker starts and the host cap.
- Reuse: the ledger's `engine_jobs` state, as `controls.running_jobs` already reads it for one run; the tile and the API answer the same figure.
