**Headline:** A system's star count can be forced (`--stars N`), the cap on it set (`--max-stars N`, 12 unless raised), and the chance of five or more stars changed (`--prevalence multi_star=PERCENT`); the host that reads them is the next step.

### Changed
- **Star count settings (GEN.267).** `SystemConfig.STARS` and `MAX_STARS` carry the forced count and the cap in the config, the run's arguments and the stored config (migration 0134, schema v134: `system_configs.stars`, `max_stars`, `prevalence_multi_star`). `planetgen system` takes `--stars N` and `--max-stars N` and the system file `stars` and `max_stars`; `sector` and `galaxy` take `--max-stars` and refuse `--stars` (it forces one system). `multi_star` is a new prevalence feature (a Generate page field, usual share 0.45% of systems, and `--prevalence multi_star=PERCENT`) that scales the chance of five or more stars; the Generate page also has a Most stars in a system field.
- **Refusals with reasons.** A count under 1, over the cap or over 64, a cap outside 1 to 64, `--stars 1` with `+binary_system` or `+wide_binary`, and two or more stars with `-binary_system` stop the run and say why.
- **Not read yet.** `StarSystem` builds no tree of three or more stars until the member-tree host (GEN.630), so a forced count changes nothing in a generated system until it lands. The defaults reproduce today's draws: no generator epoch.
