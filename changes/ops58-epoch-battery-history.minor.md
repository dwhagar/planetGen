**Headline:** A galaxy now remembers the generator epoch, the fingerprint format and the generator battery it was planned under, and the update history records a row only when something changed.

### Changed
- **The version history row (OPS.58, control schema v18).** `version_key_history` also holds the generator epoch, the generator battery's digest and its cases, and an environment record (Python, system, machine, libc, numpy, astropy, scipy and scikit-image versions). An update adds a row only when the seed, the key, the epoch, the battery digest, the lock file hash or the environment differs from the newest row; an update that changes nothing sets that row's last-seen time, so the last ten rows are the last ten changes. `planetgen versions` shows the epoch, the battery, the last-seen time and what changed from the row before. `requirements.lock` is already pinned to LF in `.gitattributes`.
- **The galaxy's record (migration 0131, schema v131).** `galaxy_shape` keeps the generator epoch, the fingerprint format (`fp_spec`) and the battery digest with its cases, written when a plan draws a new seed; `generation_runs` keeps the epoch each run generated under, so each pass of a galaxy (a scatter, a fill, a redo) says its epoch. A galaxy planned before keeps NULL in the new columns.
- **The mismatch check.** `version_check.galaxy_check` returns the epoch difference as an error (naming the release that first generated under the next epoch) and a battery difference at the same epoch as a warning naming the first case that differs. `planetgen galaxy` and `planetgen fingerprint` run the battery for it (about five seconds the first time in a process); the web pages do not.
- `tests/test_version_history.py`, `tests/test_sector_versions.py`, `tests/test_version_key.py` and `tests/test_migration_generator_epoch_record.py` (with the schema v130 fixture) cover an unchanged update, a changed lock file, an environment change, an epoch difference, a battery difference, the old control table and the old galaxy schema.
