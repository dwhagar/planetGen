**Headline:** Every sector saved in a galaxy now stores a digest of itself, and the band, shell and galaxy digests above them can be printed with `planetgen fingerprint --stored`.

### Changed
- **A leaf digest stored at save time, and the tree above it (GEN.305).** `save_sector` takes the digest of the sector in memory (`SpaceSector.to_dict()` and its address, through the canonical encoder of GEN.304, with the clocks and the collision decoration of names left out, the decoration until GEN.57) and stores it in `sectors.leaf_digest`; it also marks the sector's band node and shell node in `sector_tree_nodes` dirty, one small upsert each, so sectors saved at once by several workers never race over a node. `fingerprint_tree.refresh` rehashes the dirty nodes from what is stored (a band node reads its own wedges, a shell node its band nodes), `galaxy_root` gives the root over the shell nodes with the sector count, and `region_digest` is over a region's leaves in address order with their count, so adding a sector changes it. A node is a pure function of the leaves under it: it does not depend on the order sectors were saved in or on the number of workers.
- `planetgen fingerprint --stored` prints a line a band, a line a shell, the galaxy root and the region's digest, worked out in memory from the stored leaves (nothing is written). `planetgen fingerprint` without it prints the digests of the stored rows as before; the `leaf_digest` column is left out of them.
- An edit to a stored system does not rehash its sector's leaf yet: every writer marks its sector stale together with the storage checksum (DB.45).
- `tests/test_fingerprint_tree.py`: a node changes with every leaf and their order; every saved sector has a leaf and the stored nodes equal the tree worked out from the leaves; one seed gives one tree at 1 and at 4 workers; changing one sector changes exactly its band node, its shell node and the root; a region's digest changes when a sector is added.
