docs/plan/issue-groups.md

Boss (2026-10-15): issues are groups of TODO items, the goals we are working toward. Each row is one GitHub issue and the items it covers. scripts/build_todo_docs.py reads this table and links every item to its issues in the version plan, the TODO tree and the TODO reference; docs/generated/execution-plan.html links them too.

Rules:

  • One issue per goal. An item belongs to the issue that groups it; an item may appear in more than one row.
  • Issues Boss opened keep his text. The TODO lane adds a "TODO sync" comment that lists their items and does not edit his words.
  • Findings from any thread that belong to a goal (a failed test, a bug noticed in passing, an oddity) go to the TODO thread, which attaches them to the goal's issue as a comment headed Finding (date, source, kind) with the test or object, the failure text, whether it fails on main, how often, and a reproducer. An item with no goal yet gets a new issue.
  • Every test or investigation on an item gets a dated comment on its goal issue (fix, failure or could not reproduce), with the date and time in EDT, what was run, the result and what is needed next time; a bug that could not be reproduced or needs more information is flagged so (Boss, 2026-10-16, 11:48 PM EDT).
  • Issue labels: goal marks a goal issue; one label per TODO ID (for example GEN.250) lets the issue list filter to an item's issue. Bugs also carry bug.
  • Label upkeep (Boss, 9:18 AM EDT 2026-10-24): an item label stays on an issue only while the item is open; the TODO thread removes a label when the item is retired and deletes any label no issue carries. Process labels are goal, in progress (a lane is working an item of the goal), queued for 8.1 and paused until 8.1 (the goal's open items wait in a lane queue or for 8.1), lane: <name> (one per active lane, each with its own colour), bug, could not reproduce and needs more information; no-release goes on docs-only pull requests. Every label has a colour and the process labels a description. When a lane retires, its lane: label comes off and goes unless another goal still carries it.
  • An issue closes when every item in its row is done or dropped; the row stays so the reference page keeps its links.
  • A finished or dropped item stays in its row (Boss, 2026-10-21, 9:15 PM EDT): the pages list an open goal's finished items checked off and crossed out and its dropped items marked dropped, so the row reads as how far along the goal is. The open lists (the version plan's threads, the tree) do not list finished items; a thread of the version plan shows its finished items from docs/plan/progress-ledger.md above its open ones. Retiring an item therefore never removes its ID from a row; the label sync adds or drops GitHub labels for open items only.
