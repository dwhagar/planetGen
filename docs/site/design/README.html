Every note under docs/design/, with what it is about and where it stands. Notes are grouped in one folder per topic, and this page has one section per folder. The status words:

  • built: the design is in the code.
  • partly built: some of it is; the note's own status line says which.
  • plan: decided, not built yet.
  • research: findings and recommendations; read the note's status line for what was taken up.
  • reference: facts and measurements, not a design.
  • history: describes a design that was replaced; kept for the reasons.

Core design principle (Boss, 2026-11-08): everything in a system affects everything else in the system. Every body acts on every other body of its system by 3D position, averaged over the orbits; see system-interactions.md. A host-only or pair-only effect needs a reason registered in GEN.725.

A note's own status line, at its top, is the authority; this page only points at it. A test (src/tests/test_docs_links.py) fails when a note in a topic folder is missing from this page. A new note goes in the folder of its topic, with a row here. The architecture of the whole program is architecture.md; the decisions behind it are in design-decisions.md.

Standing rule for downloaded data (Boss, 12:47 AM EDT on 2026-10-18): Downloads of static files take place at setup (the step update.sh runs, into a cache folder outside the repository) unless the data needs to be constantly updated; any code that fetches data at run time must say in its design why the data needs constant updates (Boss, 12:47 AM EDT on 2026-10-18, project chat, as the coordinator relayed). The shared step is GEN.548; the rule and its offline test design are in gap-filling-plan.md section 6.5.

History of the design: what was chosen, dropped and replaced, and how the work moved over time, is in ../history/README.md (release headlines, decisions by month, item histories, dropped paths, and by-note.md, which links each note below to the dates and state of its items).
